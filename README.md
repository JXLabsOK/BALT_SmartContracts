# BΔLT Smart Contracts

**Bitcoin Autonomous Legacy Trust**

BΔLT is an open-source, non-custodial smart-contract ecosystem developed by **JXLabs** to bring programmable continuity, payments and digital gifting to Bitcoin and stablecoin assets.

Originally created as a decentralized inheritance and continuity protocol on **Rootstock**, BΔLT has evolved into a broader suite of autonomous smart-contract products deployed across **Rootstock and Ethereum**.

## BΔLT Ecosystem

BΔLT currently includes four main product families:

### BΔLT Continuity

Autonomous, non-custodial continuity vaults designed to protect digital assets and transfer them to a predefined beneficiary when the configured conditions are met.

The owner remains in control of the assets while active and can interact with the Vault according to the rules defined by the corresponding contract.

Supported deployments include:

**Rootstock**

* rBTC
* DoC
* USDRIF
* BPRO

**Ethereum**

* ETH
* WBTC
* USD₮
* USDC

Core capabilities include:

* Beneficiary configuration
* Inactivity-based continuity rules
* Autonomous beneficiary claims
* Owner check-ins
* Owner withdrawals while active
* Non-custodial asset management
* On-chain execution without intermediaries

---

### BΔLT Pro

BΔLT Pro extends the continuity model to organizations and treasury use cases.

It is designed for businesses and organizations that need autonomous continuity mechanisms for Bitcoin treasury assets while maintaining self-custody.

BΔLT Pro is currently available on **Rootstock Mainnet**.

---

### BΔLT Payments

BΔLT Payments provides programmable, non-custodial payment infrastructure through autonomous smart contracts.

It is designed for use cases such as:

* Contractors
* Suppliers
* Teams
* Recurring operational payments
* Business payment workflows
* Treasury-controlled distributions

BΔLT Payments supports native-asset and ERC-20/USD6 implementations, including **USD₮ on Ethereum**.

The Payments architecture includes dedicated Factory, Vault and Subscription Registry contracts.

---

### BΔLT Gift

BΔLT Gift enables users to create time-locked digital asset gifts that can be claimed by a beneficiary after a predefined release date.

Current implementations include:

**Rootstock**

* rBTC

**Ethereum**

* USD₮

BΔLT Gift supports:

* Time-locked gifts
* Designated beneficiaries
* Creator cancellation before release
* Beneficiary claim after release
* Personalized Gift Cards generated by the dApp
* QR-based claim flows
* Non-custodial asset storage
* Minimal-proxy Vault clones for efficient Vault creation

The Ethereum USD₮ implementation also sends a small ETH gas top-up directly to the beneficiary when a Gift is registered, helping the beneficiary execute the future claim transaction.

# Smart Contract Architecture

BΔLT follows a Factory / Vault architecture.

```text
User
  │
  ▼
Factory
  │
  ▼
Personal Vault
  │
  ├── Owner / Creator
  ├── Beneficiary
  ├── Asset
  ├── Rules
  └── Autonomous execution
```

Each Vault contains the rules and state associated with a specific user or use case.

BΔLT does not take custody of user funds.

Assets remain controlled by smart contracts according to predefined rules and can only move through the functions permitted by those contracts.

Different BΔLT modules use specialized Vault implementations depending on:

* Network
* Asset type
* Token decimals
* Product requirements
* Gas optimization strategy

BΔLT Gift uses OpenZeppelin minimal proxy clones to reduce the deployment cost of individual Gift Vaults.

# USD₮ Gift Economics

The current BΔLT Gift USD₮ implementation uses:

```text
Minimum Gift:       1 USD₮
Free tier:          Up to 200 USD₮
Protocol fee:       0.20%
Maximum fee:        50 USD₮
Beneficiary top-up: 0.0002 ETH
```

The protocol fee is charged in USD₮.

The ETH amount is not a protocol fee. It is transferred directly to the beneficiary wallet to help cover the future Ethereum transaction required to claim the Gift.

# Security

BΔLT is designed around:

* Self-custody
* Transparent smart contracts
* Autonomous execution
* Explicit beneficiary rules
* On-chain verifiability
* Minimal reliance on external infrastructure
* Open-source development

The original BΔLT smart-contract architecture was independently audited by **Coinspect**.

All findings and recommendations identified during the audit process were addressed before the original BΔLT mainnet launch.

Newer BΔLT modules are designed to preserve the reviewed architecture and established security patterns wherever possible.

> New contracts or product modules introduced after the original audit should not be interpreted as independently audited by Coinspect unless explicitly stated.

# Design Principles

BΔLT development follows a set of core principles:

### Non-custodial

Users interact directly with smart contracts. JXLabs does not hold private keys or custody user assets.

### Autonomous

Once configured, execution is governed by smart-contract rules rather than an administrator or centralized backend.

### Transparent

Contract source code is public and deployments can be independently verified on-chain.

### Modular

Different products and asset types use specialized Vault and Factory implementations while preserving common BΔLT architectural patterns.

### Security-first

New functionality is implemented by preserving previously reviewed patterns wherever practical and minimizing unnecessary changes to established contract logic.
